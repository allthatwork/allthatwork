You should not have to rewrite your best project from scratch for every job. Save the experience in **Career → Knowledge**, then use it when drafting answers or preparing for interviews.

Start with one useful example. You do not need to write your entire career history first.

Preferences autosave after a short pause and when you leave. Unsaved edits are kept on this browser/device. After an interrupted save, review the recovered draft before retrying it, or choose **Use saved version**. Recovered drafts never automatically replace newer server preferences. Sign-out clears account-local recovery data.

Preferences uses the same searchable currency choices as manual offers: code plus localized symbol. Offer periods start from your saved preference when the job has no pay-period hint. The timezone note stays outside the salary requirements.

## Add a fact

1. Open **Knowledge → Facts**.
2. Write a concrete statement in the fact input. Include your contribution and a measured result only when you know it.
3. Choose **Accomplishment**, **Experience**, **Skill** or **Preference**.
4. Select **Add**.

A useful fact names what you did: “I created a weekly review with sales and support to turn recurring customer questions into a prioritized backlog.” It is more useful than “I am a strong collaborator.”

After answering a clarifying question in the document assistant, **Remember** lets you review that answer as a fact, edit its wording and type, and choose its scope before saving. **Cancel** saves nothing; this explicit action makes no AI request. The saved fact remains your statement, not independently verified evidence.

Use **Source** on a fact to see where it came from. Facts you add yourself are your statements; the app does not independently verify them.

## Import facts from a file

Open **Knowledge → Import**, directly below Curate. Choose or drop a resume PDF, Word `.docx`, resume JSON (Reactive Resume v4, v5 or v6, or JSON Resume), or LinkedIn data export `.zip`. The same readers used by Documents turn the file into proposed facts. This flow creates Knowledge facts; use Documents when you want to create a resume.

Review **New facts** first, grouped by section or company. Edit the text and uncheck anything you don't want saved. **Duplicates** below compares proposed facts with matching facts in Knowledge or earlier in the file. Exact and possible duplicates start left out. Matching uses the same wording rules as Curate, without AI.

Comparisons stay in place while you edit. **Recheck matches** compares your current text with the latest Knowledge without discarding your edits. Select **Save facts** with the selected count when ready, or **Finish review** if nothing new needs saving.

Work history keeps each role and its dates; descriptions become accomplishments with company and role context. Existing bullets stay separate, while LinkedIn's flattened descriptions stay together. Education, certifications, languages and other sections become experience facts, and skills are combined into a list. Long text is split to fit the 2,000-character fact limit. Hidden resume entries start unchecked, and contact fields are left out.

LinkedIn ZIPs and JSON are read in your browser. Profile CSVs supply career facts. After a ZIP is detected, a small **LinkedIn export detected** window offers **Import facts** and **Import contacts**. Choose one or both, then select **Continue**. Only the selected CSV files are read. Contacts go into [Directory](/guides/directory). Messages are ignored. The selected facts and their original text are saved to your account after review. PDFs use your AI connection when available and the browser reader otherwise. Word files need an AI connection. Resume files can be up to 10 MB; LinkedIn archives can be up to 100 MB, with a 5 MB limit on each profile CSV and a 20 MB limit on `Connections.csv` (up to 30,000 rows). See [Importing a resume](/guides/importing-resumes) for file requirements.

New facts follow the destination group's coaching switch and privacy settings. A new group starts with coaching on. The review shows private groups and groups with coaching off. Saving doesn't run any coaching tools.

Reopening a file reads it into another review so you can compare it with Knowledge. Previously imported sources are marked **Imported before**; correct the existing fact rather than adding another copy. Saving new facts skips existing normalized text and never overwrites Knowledge. Retrying a save keeps the same source identities, so corrected, excluded, archived or forgotten facts from those sources stay as you left them.

### Contacts from the same LinkedIn export

Upload the ZIP once. Choose **Import facts**, **Import contacts**, or both in the detection window before the import readers run. Facts start selected and contacts start unchecked. Contacts-only imports skip profile files and the facts review. LinkedIn ZIP imports run locally in your browser and do not call an AI provider. Available email addresses are included with each selected contact. Use the checkbox on a contact card to include or leave out that person. Cards appear in two columns when space allows and one column on smaller screens. Contacts are grouped by company, with company groups and names sorted alphabetically.

Profile URLs identify returning contacts even if their names or employers change. Possible name duplicates start unchecked. Select a duplicate to review it, then choose an existing contact to update or **Create separate contact**. A selected duplicate needs a match decision before you can save. Selected contacts automatically bring in their companies using the names in the export. Existing companies are reused when names match, ignoring capitalization and spacing. Companies belonging only to unchecked contacts are left out.

**Import selected facts and contacts** saves both selections. Contacts-only mode uses **Import selected contacts**. Blank employer or position cells preserve existing values; manual notes, tags, phone numbers and last-contacted dates remain. Employer or position changes preserve the previous position with unknown dates. **Refresh contact review** reloads matches if another edit changed Directory while you were reviewing. A ZIP containing only connections also works. Standalone CSV import in Directory is deferred.

## Start from a resume

Open **Knowledge → Facts → Pull facts from my resume**. Choose an owned resume, then select **Review resume facts**. No resume is preselected and no AI connection receives this operation.

Review the visible career excerpts, edit their wording and type, and turn off **Save this fact** for anything you do not want kept. **Source quotation** retains the original excerpt even when you edit the fact. Select **Save selected facts** only when those statements are accurate: they become shared Knowledge available across your applications. **Cancel** discards the unsaved review. Native asks before discarding a review with proposals.

<Frame caption="Choose a resume before reviewing its facts">
  <img src="/images/guides/career/resume-facts-review.png" alt="Pull from my resume review for the fictional persona" />
</Frame>

This copies excerpts rather than inventing or verifying claims. Header contact fields and the References section are excluded, along with hidden sections and cover letters.

Visible excerpts are copied as written, including any email address or phone number typed into them. The original quotation is saved with the fact even if you edit the fact text. Deselect an excerpt if you do not want its content in shared Knowledge.

The review includes up to 50 excerpts, each at most 2,000 Unicode characters; an omitted-text notice tells you to add other facts manually. A changed or trashed resume requires a fresh review before saving. Existing facts are not overwritten, and corrected, switched-off or forgotten Knowledge is not restored by repeating an import. You can return later to save other quotations from the same resume. Your resume stays unchanged.

## Write a five-part story

Open **Knowledge → Stories → Add a story**. Give the story a clear title, add optional tags, and fill in the five parts.

| Part           | Answer this question                   | Example from a fictional project                                                     |
| -------------- | -------------------------------------- | ------------------------------------------------------------------------------------ |
| **Situation**  | What was happening before you started? | New customers were abandoning setup.                                                 |
| **Task**       | What were you responsible for?         | Help more customers finish setup without adding support work.                        |
| **Action**     | What did you personally do?            | Interviewed customers, reviewed the funnel and worked with design on a shorter flow. |
| **Result**     | What changed, and how do you know?     | A measured improvement, if you have the records to support it.                       |
| **Reflection** | What did you learn?                    | Define success measures before starting the next rollout.                            |

A story needs a title, Situation, Task and Action; the form marks only Result and Reflection as optional. Leave Result blank if you cannot support the outcome. A story can still be useful without a number. Reflection can also stay blank until you have something useful to add.

If a required part is blank, **Save story** names each missing part beside its field and moves focus to the first one. Your draft stays in the editor so you can finish it. Result and Reflection remain optional.

Under **Backed by**, select the facts that support the story. Then select **Save story**.

When you arrive through an interview plan's **Draft story**, its title and note come with you. Only its cited active shared facts start selected; review or untick them before saving. Opening the draft saves no story. See [Draft a story from a preparation plan](/guides/preparing-for-interview-day#make-a-plan-before-the-day).

## Reuse the story

- In **Apply**, add a form question and choose **Draft** to draw on relevant Knowledge.
- In **Interview prep**, open the stories suggested for the interview, or draft one that is missing.
- In **Practice**, rehearse a question using your story, then review feedback.
- In **Coach**, keep **Knowledge** on when you want those facts and stories included with your message.
- In the document assistant, turn on **Use Knowledge** to let it look up switched-on facts and cite them when tailoring a resume. It's off by default, and only facts, not stories, are used. See [Using the assistant](/guides/using-the-assistant#use-knowledge).

In **Knowledge → Stories**, **Practice** names the upcoming interview or lets you choose its company and round. If there are no upcoming interviews, it opens **Practice without an application**. No job or interview is created. You can type or speak an answer, review what the provider receives, and request feedback. Each saved attempt stays with that story; leaving and reopening keeps an unfinished answer on this device. Shared practice uses only facts and stories available to all applications, so an employer's private Knowledge is left out. A story without supporting facts, with switched-off facts, or with facts changed since the story was saved cannot be practised until you link or review its facts. The same choices are available in the native app.

## Correct an old fact

Select **Correct** on the fact. Edit its text, **Fact type**, or **Scope**. Choose **All applications** for shared Knowledge, or an application to keep the fact private to that job. Select **Save correction** on web or **Save fact** on native mobile. The changes save together; earlier text remains in correction history. Type and scope corrections also flag linked stories for review. Switching a fact off and on again doesn't flag its stories, since the fact itself didn't change.

If another edit or removal happened while the correction was open, the save stops and your draft stays open. Close the correction, review the current fact, then reopen it to make the changes you still want. A failed connection also keeps the draft open for retry. Native asks before discarding changes to text, type or scope. Older self-hosted servers need an update before these correction controls can save; a failed correction does not fall back to saving only its text.

Open each flagged story, check the affected claims, edit them and save the story again. Review older drafts too; correcting Knowledge does not rewrite documents or messages you already sent.

A flagged story is excluded from new coaching until you review and save it. Unfinished story text stays in this browser tab when you navigate or refresh. **Practice** opens the selected story in the workspace of an upcoming interview: it names the company when there's one interview, and lists them when there are several. It's unavailable, with the reason on hover, until the story is linked to at least one fact, while a fact it uses is switched off or was corrected after the story was saved, or when no interview is coming up. A missing story link shows an error instead of opening another story.

## Keep a detail for one job

Application notes belong to that application. A debrief can also suggest remembering a detail **for that company only**, such as what an interviewer asked you to explain next time.

Facts show their scope. **Correct → Scope** can restrict a shared fact to one job or move it to another application. Choose **Use for all applications** only when a private fact is useful beyond that job. This changes its scope, not its truth. Previously written documents and messages are not rewritten or recalled.

### Use a shared fact for some jobs only

Some facts should reach the AI only for certain jobs, such as a security clearance for government roles. Put them in a group and select its lock in **Curate → Groups**. A locked group is private; its subgroups show a dimmed lock, since they're private through it. A private group's facts, and its subgroups', never go to your AI provider, whatever their own switches say. They stay in Knowledge, and you can still correct or forget them.

To use them for one job, open the application and switch the group on under **Knowledge for this job** in its details. Fit, Apply, Prepare, Practice, Debrief, Messages and that job's coach then read those facts, switched off or not; every other job still doesn't. Nothing is copied, so a correction to a fact applies to every job that uses it.

**Knowledge for this job** can also **Include** or **Leave out** any other group, for example to keep an unrelated past role out of one application. A choice for a single fact, made through the API (`PUT /career/overrides` with a `factId`), wins over its group's.

## Stop using or forget a fact

Switch **Used in coaching** off to keep the fact in your account while excluding it from new coaching context. A switched-off fact cannot support a story sent to the coach.

Select **Archive** to retire a fact you no longer use, such as an old skill, without erasing it. An archived fact never goes to the AI, even when its group is switched on or an application includes it, and it's hidden from the list. Choose **Archived** above the list to see archived facts, and **Restore** to bring one back, switched on.

Select **Forget** to remove the fact and its evidence links. Use **Undo** within the six-second notice if you change your mind. The original resume, file or message is not deleted, and copies already exported or sent to a provider remain outside this action. See [Your data](/guides/career-workspace-reference#your-data).

The notice appears once the removal is ready. Leaving the page ends the Undo window and starts the pending removal. Undo cancels that pending action; it cannot recover content already forgotten elsewhere. If the saved state cannot be checked, the fact stays hidden and **Retry** checks it again before showing anything.

Turn on **Show forgotten** to confirm the recorded number of forgotten facts and when they were forgotten, in your account timezone. This view contains counts and timestamps only. It does not reveal earlier wording, source quotations or correction history, and it cannot restore a forgotten fact. Facts belonging to an application in Trash stay out of this view until that application is restored.

## Group facts and switch them together

Put related facts in a group, such as one per job or a group for anything you rarely want sent. Select **Group** on a fact and type a name, or pick one already in use. Use slashes for levels: `experience/acme` sits under `experience`. To add facts straight into a group, choose it in the **Group** filter first; new facts you add go into it.

**Career → Knowledge → Curate → Groups** lists every group with a lock and a switch. Under its name it shows how many facts it holds (or how many are on and off, when some of each), and how many characters its switched-on shared facts add to the budget, or "private" when it's locked. The switch is on when anything in the group is on. Switching it turns every fact in the group and its subgroups on or off at once. Every row ends with **new facts default: on** (green) or **off** (red): how a fact added to the group later starts. Switching the group sets it, so a group you switched off stays off as it grows. Select **on** or **off** to change only the default: the facts already in the group, and its switch, stay as they are. A group with no default of its own follows the nearest group above it, and starts facts switched on when none has one. Switching a parent group again also resets any subgroup you switched on its own.

## Clean up duplicates

A fact said twice takes twice the budget. **Curate → Duplicates** finds facts with the same text, ignoring case, accents, punctuation and spacing, and facts that say nearly the same thing.

- **Remove copies** folds every word-for-word copy of a shared fact that sits in an application into the shared fact. The shared fact already reaches that application; if it's switched off or in a private group, it's included for that application instead, so nothing that application used goes missing. Saving a new copy of a shared fact to an application does the same straight away.
- **Keep one, archive the copies** keeps one of a set of identical facts, the oldest one that's switched on.
- For two facts with nearly the same words, or where the longer one says almost everything the shorter one does, choose **Keep this, archive the other** on the one you want. If you keep a fact that belongs to one application over a shared one, it becomes shared, so every application gets it, and it takes the other's group if it has none. **Not duplicates, keep both** hides the pair in this browser, for example a short and a long form you want to keep.
- A long fact shows its first four lines; **Show more** shows the rest, and **Show less** cuts it again.

Keeping one archives the other: it's hidden and never sent, and you can restore it from **Archived** in Facts. Its stories, saved results and per-application choices move to the one you keep, so nothing is erased by accident.

## Fix stories the AI can't use

**Curate → Stories the AI can't use** lists each story that isn't sent and why: a fact behind it is switched off, archived, in a private group or forgotten, or was corrected after the story was saved. For a correction it shows the fact's text then and now. If the story still holds, select **Still true, use it** to confirm it as it is; otherwise **Edit story**.

## Review Knowledge with AI

**Curate → Knowledge review** checks your facts for upkeep on your default AI connection. First it removes application copies of shared facts, which needs no judgment. Then it asks the AI which facts disagree, which are older figures that a newer fact replaces (a team that grew, a count that went up), and which claim a result with no date, place or project to check it by.

It sends only your shared facts that already reach the AI: private groups, switched-off and archived facts are never sent. Each request stays within **Size of one batch** (left blank, **Facts in each action** plus **Stories in each action**) and the action time limit; a large Knowledge goes in up to **Batches in one review** requests (8 by default), by group, and the summary says how many facts were read. Your provider may charge for each request.

Only judgment calls are listed, since only you can answer them. For each one choose **Archive this one** on the wrong or outdated fact, **Keep the newer one**, **Correct it**, or **Not a problem**. A finding goes away once a fact in it is archived or forgotten. **Review again** replaces the last review.

| **Length of structured answers**                    | Provider default  | Answers in a fixed shape: actions, reviews, Improve and reading postings.              |

The facts and stories that best match go in first: in application actions, the ones that match the posting and the task, such as the form question or the recruiter's message; in Coach, the ones that match your message, and the posting too when the application is shared. Matching is by shared words, counting different forms of a word as one (migrated, migration) and rare words like a tool's name more than common ones. Facts that match nothing still fill any space left, newest first, so a fact worded differently from the posting can still go in. A knowledge search finds facts and stories containing any of its words, best match first. In application actions, a story goes in only when every fact behind it does. Anything longer than its limit is cut at the limit, so raise **Targeting note in each action**, for example, when your targeting notes are long and you want Fit to read all of it. The defaults suit fast models with small context windows; raise them when your model can read more or needs more time. Larger Knowledge limits send more of your Knowledge to your AI provider, and each request takes longer and costs more. A reply that reaches its time limit keeps what it wrote so far and asks you to continue; any other request that reaches its time limit stops with a message naming the limit to raise. Three limits can be left blank, and are by default: **Conversation kept in view** then fits half your AI connection's context window (the one the Knowledge budget uses), never less than 40,000 tokens, and 40,000 when the window isn't known; **Size of one batch** follows the action limits; and **Length of structured answers** leaves the length to your provider. **Reset to defaults** puts every limit back and empties those three. Time limits for web searches, page reads, job boards and scheduled discovery runs, and how much of a page or a search is kept, are under **Web access** on the same page.

### See how much of the budget you use

**Career → Knowledge → Curate** and **AI limits** show a **Knowledge budget** meter. It measures your shared, switched-on facts and the stories still backed by them in the same JSON characters the limits use, and shows how many the Coach shares with each message. When the facts or stories don't all fit, it says so: each action sends the best matches first and leaves out the rest.

It also estimates the tokens an action sends, at about four characters a token, counting the posting, requirements, notes, contacts and documents that go with it at their limits, and compares the largest request your limits allow with your default AI connection's context window. The window comes from [models.dev](https://models.dev). For a model it doesn't list, such as a gateway alias, select **Set it** and enter the window in tokens; it's saved on that connection. When the limits outgrow the window, the meter warns you, so you can lower them before requests get cut off.

## Keep application details private

Open **Settings → Application profile**. Enter application-only contact details, address, links, country-specific work authorization and sponsorship answers, relocation willingness, requested salary and references. These details are stored separately from resumes and Career knowledge; editing them needs no AI connection.

Blank details and missing countries remain unknown. Choosing an address country does not answer authorization or sponsorship questions. Add a country and choose **Yes**, **No** or **Unknown** for each question. Enter and correct references yourself; the app does not infer them or contact them.

Use **Career preferences** for existing work locations, office days, notice period and minimum base salary. Requested salary has its own amount, currency and pay period, and never copies your minimum automatically. On web, select **Edit**, **Add** or **Answer** beside a row, review the fields and save that edit. **Cancel** leaves the saved row unchanged.

Private profile fields are never automatically added to public resume links, PDF/DOCX or other document exports, coach context or MCP tool results. If you deliberately copy a detail into a document or application answer, it becomes part of that content and follows that content's sharing and AI controls. Submitted answers and document versions remain unchanged when the profile later changes or is deleted.

**Export** at the top of the page downloads a JSON record containing its data, last-updated date and revision. **Export everything** also includes it. **Delete profile** at the bottom of the page removes the saved private profile and references after confirmation; it leaves Career preferences and previously submitted answers unchanged. Downloaded or shared copies cannot be recalled. [Export your data](/guides/exporting-your-data) before deletion if you need a copy.

Self-identification answers are not collected in this phase. A future extension needs a separate consent, category and retention-policy review, and must keep those answers out of AI prompts.

When a guest account is linked to a permanent account, a private profile transfers if the permanent account has none. If both have profiles, linking stops rather than choosing or merging answers. Export and delete one profile from **Settings → Application profile**, then retry linking. Authorized API credentials with read permission can read the profile; write and delete permissions are checked separately. Share credentials only with integrations you intend to trust with this data.

Preferences also offers optional [target-role suggestions](/guides/finding-roles-automatically#optional-role-suggestions). Select the AI connection and choose whether to share a resume and/or enabled shared Knowledge. Cited statements stay user records, not confirmed qualifications. Suggestions remain drafts until you edit and use them; no search, schedule, fact or answer is created automatically. Private application facts, the application profile and saved answers are excluded.

Fit’s explicit **Add evidence** can be followed by **Propose a resume bullet**. That separate request sends only the selected statement, linked resume and posting to the existing assistant. Saving Knowledge alone never mutates a resume. See [checking fit](/guides/checking-job-fit).
